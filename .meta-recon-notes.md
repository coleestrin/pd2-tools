## Where items/skills live

**Skills:** Stored in the separate `CharacterSkills` table (normalized). Each row is one (character, skill) pair with `skill_level`. This is the **base level from the character file** — NOT item-boosted. Item skill bonuses are computed in-memory by `calculateTotalSkills()` (see `api/src/utils/skill-calculator.ts`) and attached to the response as `realSkills[]` at serve time. The `full_response_json` JSONB also contains the raw PD2 API payload with `character.skills[]` and `realSkills[]`.

**Items:** Stored in the separate `CharacterItems` table (normalized). Each row is one equipped item: `base_item_id`, `quality_id`, `is_runeword`. Item properties/modifiers are NOT stored in a separate `character_item_modifier` table — they exist only inside `full_response_json` as the full API payload. The `full_response_json` items have a `properties[]` string array (e.g. `"+2 to All Skills"`, `"20% Faster Cast Rate"`).

**Mercenary:** One row per character in `CharacterMercenaries` (`description` text = merc type string). Merc items in `MercenaryItems` (same shape as `CharacterItems`, keyed by `character_db_id`).

## Filter pattern from characters.ts

Query params are destructured from `req.query` directly (no Zod, no express-validator):

```ts
const { gameMode = "softcore", page = "1", pageSize = "50",
        minLevel, maxLevel, classes, items, skills,
        mercTypes, mercItems, season } = req.query;
```

`classes`, `items`, `mercTypes`, `mercItems` are comma-separated strings → `split(",")`.
`skills` is URL-encoded JSON: `JSON.parse(decodeURIComponent(skills as string))` → `[{ name, minLevel }]`.
`season` defaults to `config.currentSeason` if not provided.

The filter is assembled as a `CharacterFilter` object and passed to `characterDB.getFilteredCharacters()` which builds a CTE:

```sql
WITH FilteredCharIDs AS MATERIALIZED (
  SELECT C.character_db_id FROM Characters C
  [JOIN Classes CL ON C.class_id = CL.class_id]  -- if classes filter
  WHERE C.game_mode_id = $1
    AND C.season = $N           -- always set
    AND C.level >= $N           -- if minLevel
    AND C.level <= $N           -- if maxLevel
    AND CL.name IN ($N, ...)    -- if classes
    AND EXISTS (                 -- per item (AND logic)
      SELECT 1 FROM CharacterItems CI
      JOIN BaseItems BI ON CI.base_item_id = BI.base_item_id
      WHERE CI.character_db_id = C.character_db_id AND BI.name = $N
    )
    AND EXISTS (                 -- per skill (AND logic)
      SELECT 1 FROM CharacterSkills CS
      JOIN SkillsDefinitions SD ON CS.skill_def_id = SD.skill_def_id
      WHERE CS.character_db_id = C.character_db_id
        AND SD.name = $N AND CS.skill_level >= $N
    )
    AND EXISTS (                 -- merc types (OR logic via IN)
      SELECT 1 FROM CharacterMercenaries CM
      WHERE CM.character_db_id = C.character_db_id AND CM.description IN (...)
    )
    AND EXISTS (                 -- per merc item (AND logic)
      SELECT 1 FROM MercenaryItems MI
      JOIN BaseItems BI ON MI.base_item_id = BI.base_item_id
      WHERE MI.character_db_id = C.character_db_id AND BI.name = $N
    )
)
```

Response shape for `GET /api/characters`:
```json
{ "total": 1234, "characters": [...fullResponseJsonArray], "breakdown": { "Amazon": 10, "Sorceress": 20, ..., "total": 1234 } }
```

Response shape for single character (`GET /api/characters/:name`): the raw `full_response_json` JSONB directly (not wrapped).

Response shape for account characters: `{ "characters": [...], "total": N }`.

## Caching pattern

```ts
export function autoCache(ttl: number = 900) {
  return async (req: Request, res: Response, next: NextFunction) => { ... }
}
```

- Applied per-handler as Express middleware: `router.get("/", validateSeason, autoCache(900), handler)`
- **All** existing route handlers use `autoCache(900)` (15 minutes)
- Cache key: `auto:${req.path}:${sha256(sortedNormalizedQueryParams)}`
- Backed by Redis via `getCacheValue` / `setCacheValue` from `api/src/utils/cache.ts`
- Cache write is fire-and-forget (non-blocking)
- Only caches GET requests; passes through for other methods

Our `/meta` route should use the same pattern:
```ts
router.get("/", validateSeason, autoCache(900), async (req, res) => { ... });
```

## Error-handling pattern

There is an `AppError` interface (`statusCode?: number, isOperational?: boolean`) in `api/src/middleware/error-handler.ts`, but the route handlers do **not** use it. Instead they use:

```ts
res.status(400).json({ error: { message: "..." } })   // validation failures
res.status(404).json({ error: { message: "..." } })   // not found
res.status(500).json({ error: { message: "..." } })   // unexpected errors
```

Pattern: `{ error: { message: string } }` envelope, always.
For 400 validation, the `validateQueryParams` middleware adds an `allowedParams` field too:
```json
{ "error": { "message": "Invalid query parameters: foo", "allowedParams": [...] } }
```

There is NO `HttpError` class being thrown in route handlers — they catch and call `res.status().json()` inline.

## Response-shape convention

Plain responses — NOT wrapped in `{ data, meta }`:

- Filtered characters: `{ total, characters[], breakdown{} }`
- Single character: flat `full_response_json` object
- Item/skill/merc usage stats: plain array `[{ item, itemType, numOccurrences, totalSample, pct }]`
- Level distribution: `{ softcore: [{ level, count }], hardcore: [{ level, count }] }`
- Account characters: `{ characters[], total }`
- Snapshots: `{ snapshots[], total }`

Our `/meta` route should return a plain object, not `{ data: ... }`.

## `realSkills` clarification

`CharacterSkills.skill_level` = **base level** (from character save file). Does NOT include item bonuses.

`realSkills[]` is a computed array added to responses at serve time. It's calculated by `calculateTotalSkills()` in `api/src/utils/skill-calculator.ts`, which parses item `properties[]` strings (e.g. "+2 to All Skills") and sums bonuses on top of base levels.

For the `/meta` cohort skill-usage query, we have two choices:
1. Use `CharacterSkills.skill_level` — fast (indexed), but only base levels. A skill at base 0 with +10 from items = invisible.
2. Mine `full_response_json->'realSkills'` via JSONB — slower, but reflects equipped bonuses. Already populated in JSONB by the scraper.

The existing `analyzeSkillUsage` method uses `CharacterSkills` (option 1) with `skill_level >= 20` as the cutoff. For consistency with the existing stats endpoints, Tasks 5-9 should use option 1 (CharacterSkills table) and expose the `minLevel` parameter for callers.

## Plan-assumption mismatches

| Plan assumption | Reality |
|---|---|
| Table name `character` (singular) | Actual: `Characters` (plural, PascalCase — postgres will lowercase to `characters`) |
| Table name `character_skill` | Actual: `CharacterSkills` |
| Table name `character_item` | Actual: `CharacterItems` |
| Table name `character_mercenary` | Actual: `CharacterMercenaries` |
| `character.game_mode` column | Does NOT exist. Game mode is a FK: `Characters.game_mode_id → GameModes.game_mode_id`. To filter by mode, join GameModes or resolve game_mode_id from the name first (via `getOrInsertLookupId`). |
| `character.class_name` column | Does NOT exist. Class is a FK: `Characters.class_id → Classes.class_id`. Join `Classes CL ON C.class_id = CL.class_id` to get `CL.name`. |
| Item modifiers in a separate table | NOT in a separate table. Properties are strings in `full_response_json->'items'->[i]->'properties'[]` JSONB only. |
| Merc joins via merc_id | MercenaryItems joins via `character_db_id` directly (no separate merc_id). |
| `requiredSkills[].minLevel` filters base level | Correct — `CharacterSkills.skill_level` is base level, not effective level. |
